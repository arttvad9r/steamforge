## Краткое описание

**Стимпанк-головоломка 2048 с мастерской, прогрессией и Overdrive**

## Полное описание

Steamforge — атмосферная головоломка на основе механики объединения плиток. Вместо абстрактной таблицы чисел работает механическая мастерская: детали объединяются во всё более сложные механизмы, пока фабрика не доберётся до Механического ядра.

Объединяйте одинаковые детали, планируйте ходы и не позволяйте полю заполниться. Числовые значения остаются крупными и читаемыми.

### Давление и Overdrive

Удачные объединения повышают Steam Pressure. Заполните систему, чтобы запустить короткий Overdrive с усиленным набором очков.

### Развитие мастерской

Партии развивают мастерскую и дают ресурсы. Открывайте достижения, выполняйте контракты и собирайте элементы коллекций.

### Ежедневные цели

Daily Challenge и ежедневные цели дают дополнительную причину вернуться, не блокируя обычную игру.

### Работает офлайн

Основной gameplay, локальный прогресс и восстановление партии работают без постоянного подключения к интернету. Steamforge не содержит рекламы и не использует AppMetrica или другой SDK пользовательской аналитики.

Сетевое разрешение может использоваться только отдельными продуктовым сервисами, например опциональным Remote Config и будущим Weekly backend, если соответствующие функции включены в production-конфигурации.

Особенности:

- поле 4×4 и знакомая механика 2048;
- premium industrial-steampunk визуальная система;
- Steam Pressure и Overdrive;
- Workshop progression, ресурсы и достижения;
- Contracts и Blueprint Collection;
- Daily Challenge / return loop;
- Undo и Wrench;
- автоматическое сохранение и process-death restore;
- полноценный offline-safe core;
- без рекламы и рекламных SDK;
- без пользовательской аналитики/телеметрии.

## Категория

Предпочтительно: **Игры → Головоломки**.

## Возрастная категория

Предварительно: **0+**. Финальную категорию подтвердить по фактическому production content в Консоли RuStore.

## Скриншоты

Использовать только реальные production-like кадры интерфейса, одной ориентации и без системных/debug элементов.

Приоритетный набор:

1. **Gameplay** — крупное читаемое поле и Steam Pressure;
2. **Workshop** — развитие мастерской;
3. **Contracts / Blueprints / Profile** — один наиболее сильный meta-screen текущего релиза.

Settings можно использовать как дополнительный кадр, если он визуально полезен. В нём не должно быть analytics/ad/consent секций — их в продукте больше нет.

Workflow `RuStore Store Assets` должен генерировать изображения из фактического UI. Перед загрузкой визуально проверить каждый artifact.

## Иконка

Store icon должна соответствовать launcher icon текущей production версии. Перед публикацией проверить актуальные требования RuStore по размеру/формату в Консоли.

## Контакты и privacy

Перед публикацией заполнить:

- support e-mail;
- owner/developer name;
- privacy/data page URL, если это требуется актуальными правилами RuStore/применимым правом.

Privacy page должна соответствовать фактическому tracking-free клиенту и описывать только реально используемые local/network data flows.

## Данные владельца перед релизом

Нужны:

- имя/наименование владельца;
- support/privacy e-mail;
- release keystore и пароли + backup;
- final store/launcher icon;
- package ID confirmation;
- при включённом Remote Config — production endpoint и сведения о server logs/privacy.

**Не нужны и не должны запрашиваться:**

- AppMetrica API key;
- Rewarded/Interstitial ad unit IDs;
- advertising consent configuration.

## Перед отправкой на модерацию

- использовать signed artifact из `tools/build-rustore-release.sh`;
- проверить подпись и SHA-256;
- пройти physical-device smoke;
- убедиться, что приложение сразу открывает Home без analytics/ad consent gate;
- убедиться в отсутствии рекламных/analytics UI и SDK в final artifact;
- проверить фактические сетевые endpoints production-конфигурации;
- загрузить минимум требуемое RuStore число реальных скриншотов;
- проверить карточку на отсутствие placeholder/demo/устаревших рекламных обещаний;
- для первого релиза предпочесть ручную публикацию после модерации.
